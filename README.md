# MCPex

**원하는 AI 모델을 연결하고, 나만의 에이전트를 만들어 작업을 위임하세요.**

MCPex는 클라우드 API와 로컬 추론 서버의 모델을 하나의 화면에서 관리하고, 사용자 정의 에이전트를 MCP(Model Context Protocol) 도구로 제공하는 로컬 서비스입니다. 같은 모델로 문서 요약, 설계 검토, 코드 조사, 코드 수정 등 서로 다른 역할의 에이전트를 만들 수 있습니다.

단순한 API 프록시를 넘어, 에이전트별 시스템 프롬프트·입출력 형식·파일 도구·실행 범위를 구성할 수 있습니다. 도구 사용 모드에서는 모델 응답과 파일·명령 실행을 반복하여 작업 결과를 반환합니다.

## 주요 기능

- **공급업체 선택:** API 클라우드 모델과 로컬 추론 서버를 연결합니다. 브라우저 채팅 서비스 자동화는 대상이 아닙니다.
- **프로바이더와 모델 분리:** 접속 정보는 프로바이더에, 모델 ID와 기본 생성 옵션은 모델에 등록합니다.
- **에이전트 구성:** 기본 템플릿에서 시작해 프롬프트·입출력·도구를 편집합니다.
- **시험 후 공개:** 초안으로 시험하고 적용한 버전을 활성화해 도구로 제공합니다.
- **파일 작업:** 탐색·읽기·검색·작성·부분 교체와 허용 명령 실행을 지원합니다.
- **실행 확인:** 진행 상태, 최종 답변, 오류와 실행 기록을 확인합니다.
- **설정 관리:** 개인 템플릿, 설정 내보내기·가져오기, 기록 보존 및 DB 백업을 제공합니다.

MCPex 서버 하나가 여러 활성 에이전트를 각각 별도의 도구로 제공합니다. 프로바이더나 모델 등록만으로 에이전트가 자동 생성되지는 않습니다.

> 개발 중인 프로토타입입니다. 모의 모델·SDK·브라우저 검증과 실제 외부 모델·클라이언트 검증을 구분해 관리합니다. 현재 검증 환경은 Windows와 Node.js 24이며 Windows 현재 사용자 DPAPI로 비밀값을 저장합니다. 전체 파일 접근 정책과 외부 네트워크 운영은 아직 구현된 사용 기능이 아닙니다.

## 설치하고 설정 화면 열기

준비물: **Windows, Node.js 24 이상, npm 11 이상, Git**, 사용할 모델의 API 접속 정보 또는 실행 중인 로컬 추론 서버.

PowerShell에서 실행합니다.

```powershell
git clone https://github.com/totjae/mcpex.git
cd mcpex
npm ci
npm run build
node .\apps\cli\dist\src\index.js open
```

설치·빌드 후에는 프로젝트 폴더의 **MCPex Settings.vbs**를 더블클릭해 설정 화면을 열 수 있습니다. 설정 데이터를 담은 파일이 아니라 설정 화면 실행기이며, 프로젝트 폴더와 빌드 산출물을 함께 유지해야 합니다.

서비스가 없으면 백그라운드로 시작하고 이미 실행 중이면 재사용합니다. 브라우저 창을 닫아도 서비스는 유지됩니다. 로컬 추론 서버 실행과 모델 로딩은 MCPex가 대신하지 않으므로 해당 프로그램에서 준비하세요.

업데이트는 프로젝트 폴더에서 `git pull`, `npm ci`, `npm run build` 순서로 진행합니다. 실행 중인 서비스는 기존 코드를 사용하므로 작업이 끝난 뒤 재시작해야 변경된 서버 코드가 반영됩니다.

## 첫 에이전트 만들기

1. **프로바이더:** 프로필을 선택하고 실제 기본 URL과 API key/token을 입력해 등록합니다. 인증을 요구하지 않는 로컬 서버는 키를 비울 수 있습니다.
2. **모델:** 프로바이더를 선택하고 모델 목록을 조회하거나 실제 모델 ID를 등록합니다. 응답 시험으로 연결을 확인합니다.
3. **에이전트:** 이름·도구 이름·모델·템플릿을 선택해 생성합니다. 처음에는 일반 응답 템플릿으로 파일 설정 없이 시험할 수 있습니다.
4. **편집:** 프롬프트와 입출력 설정을 확인합니다. 파일 작업에는 실행 모드·작업 폴더 정책·허용 도구가 모두 필요합니다.
5. **시험:** 초안을 저장하고 시험 입력을 작성해 실행합니다. 완료 후 같은 화면에서 답변을 확인합니다.
6. **적용·활성화:** 적용 버전을 생성한 뒤 활성화합니다. 초안 저장만으로 공개 도구 설정이 바뀌지는 않습니다.

### 프로바이더

프로바이더는 **모델을 호출할 서버와 접속 방식**입니다. 같은 서버의 여러 모델은 프로바이더 하나를 공유할 수 있습니다.

| 항목                  | 의미와 사용 예                                                                                                                              |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 이름                  | 화면에서 구별할 이름입니다. 예: 내 로컬 서버, 클라우드 API.                                                                                 |
| 프로필                | 공급업체별 어댑터·URL 기본값을 채우는 프리셋입니다. 실제 접속 정보가 맞는지 확인합니다.                                                     |
| 어댑터                | API 요청·응답을 변환하는 방식입니다. OpenAI 호환, Anthropic, Gemini, Vertex AI, Bedrock 구현이 있습니다. 사용하는 API 형식에 맞춰야 합니다. |
| 기본 URL              | API 서버 주소입니다. 채팅 웹페이지 주소가 아닙니다.                                                                                         |
| API key / token       | 공급업체가 발급한 인증값입니다. 연결하는 계정의 요금과 권한이 적용됩니다.                                                                   |
| Project ID / Location | Vertex AI 등 해당 프로필에서 사용하는 프로젝트와 위치입니다.                                                                                |
| 최대 동시 실행        | 이 프로바이더를 사용하는 작업의 동시 실행 상한입니다. 범위는 1~8이고 초과 작업은 대기합니다.                                                |
| 리소스 그룹           | 다른 프로바이더가 같은 GPU나 공용 자원을 쓸 때 묶는 이름입니다. 같은 문자열이면 같은 그룹이며 독립 자원이면 비울 수 있습니다.               |
| 그룹 동시 실행        | 같은 그룹 전체의 동시 작업 상한입니다. 범위는 1~8이고 그룹명이 없으면 공유 그룹 제한은 적용되지 않습니다.                                   |

**리소스 그룹 예:** 두 로컬 프로바이더 A·B가 같은 GPU를 사용한다면 둘 모두 그룹을 `local-gpu`, 그룹 동시 실행을 `1`로 설정합니다. A가 실행 중이면 B는 기다립니다. 각 프로바이더의 최대 동시 실행이 2여도 그룹 전체 제한은 1입니다.

같은 그룹의 제한이 서로 다르면 **구성원 중 가장 작은 값**이 적용됩니다. 전역 제한·프로바이더 제한·그룹 제한과 작업 폴더 잠금이 모두 적용됩니다. 같은 폴더 또는 포함 관계의 폴더 작업은 충돌 방지를 위해 순서대로 실행됩니다.

프로바이더 삭제는 소속 모델이 남아 있으면 차단됩니다. 먼저 참조 에이전트와 모델을 정리하세요. 프로필 제공은 모든 공급업체의 실계정 연결 검증 완료를 의미하지 않습니다.

### 모델

모델은 **프로바이더 안에서 실제로 호출할 모델 ID와 기본 옵션**입니다.

| 항목                | 설명                                                                                            |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| 프로바이더          | 이 모델을 제공하는 등록 서버입니다.                                                             |
| 모델 ID             | API가 인식하는 정확한 ID입니다. 별칭과 다를 수 있으므로 조회 결과나 공급업체 설정을 확인합니다. |
| 기본 생성 설정 JSON | 모델에 연결된 에이전트들의 기본 생성 옵션입니다. 기본값을 따르려면 `{}`로 둘 수 있습니다.       |
| 응답 시험           | 짧은 프롬프트로 접속·모델 ID·응답을 확인합니다. 에이전트 파일 작업 시험과는 별도입니다.         |

생성 설정 예시:

```json
{
  "temperature": 0.3,
  "topP": 0.9,
  "maxOutputTokens": 2048
}
```

`temperature`는 응답 선택의 다양성, `topP`는 선택 후보 확률의 범위, `maxOutputTokens`는 출력 길이 상한에 관련된 값입니다. 공급업체·모델별 지원 범위가 다르므로 오류가 나면 기본값 `{}`부터 시험하세요. 같은 항목을 에이전트에서 재정의하면 모델 기본값보다 우선합니다.

참조 중인 모델은 삭제할 수 없습니다. 초안뿐 아니라 적용 버전의 참조도 확인해야 합니다. 모델·프로바이더 설정 변경을 공개 에이전트에 반영하려면 에이전트를 다시 적용합니다. 인증값 변경은 이후 호출에서 현재 저장된 값을 사용합니다.

### 에이전트와 템플릿

에이전트는 **모델 + 역할 지시 + 입출력 규칙 + 실행 권한**의 조합입니다.

| 항목                 | 설명                                                                                                                        |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 표시 이름            | 관리 화면에서 알아보기 위한 이름입니다.                                                                                     |
| 도구 이름(toolName)  | 고유 식별자입니다. 영문 소문자로 시작하고 소문자·숫자·밑줄을 사용하며 최대 48자입니다. `mcpex_` 접두사는 예약되어 있습니다. |
| 도구 설명            | 어떤 일을 언제 위임하면 되는지 설명합니다. 역할·입력·결과를 구체적으로 적습니다.                                            |
| 시스템 프롬프트      | 역할·작업 원칙·답변 방식을 지시합니다. 문장만으로 파일 권한이 생기지는 않습니다.                                            |
| 사용자 메시지 템플릿 | `{{input.task}}`처럼 입력 키로 실제 메시지를 만듭니다. 코드·환경변수는 실행하지 않습니다.                                   |
| 입력 JSON Schema     | 필요한 필드·타입·필수 여부를 정의합니다. 최상위 타입은 object입니다.                                                        |
| 출력 형식            | Markdown 또는 JSON을 선택합니다. JSON은 출력 스키마 검증을 사용할 수 있습니다.                                              |
| 실행 모드            | 응답만은 모델 답변을 생성하고, Workspace 도구는 선택된 파일·명령 도구를 사용합니다.                                         |

간단한 입력 스키마:

```json
{
  "type": "object",
  "properties": {
    "task": { "type": "string", "description": "위임할 작업" }
  },
  "required": ["task"],
  "additionalProperties": false
}
```

이 스키마의 입력 예는 `{"task":"요구사항을 검토해 주세요."}`입니다. 필드를 `question`으로 바꾸면 메시지 템플릿도 `{{input.question}}`을 사용해야 합니다. 메시지 미리보기로 확인하세요.

**저장·적용·활성화의 차이**

| 동작                         | 바뀌는 것                                                                                     |
| ---------------------------- | --------------------------------------------------------------------------------------------- |
| 초안 저장                    | 편집 내용을 저장하며 공개 버전은 유지합니다.                                                  |
| 시험 실행                    | 저장한 초안으로 실제 모델을 호출합니다. 공개하지 않고 확인할 수 있습니다.                     |
| 적용 버전 생성               | 현재 설정을 실행용 버전으로 고정합니다. 활성 에이전트는 이후 호출부터 새 버전을 사용합니다.   |
| 활성화                       | 적용된 에이전트를 도구로 제공합니다.                                                          |
| 비활성화                     | 새 호출을 막고 재시작해도 상태를 유지합니다. 이미 접수된 실행 취소는 별도입니다.              |
| 미저장 편집 취소 / 초안 복원 | 저장 전 변경 취소와 적용 버전으로 저장 초안 복원을 구분합니다. 공개 버전을 지우지 않습니다.   |
| 삭제                         | 비활성 에이전트를 목록에서 제거합니다. 현재 정책에서는 삭제한 toolName을 재사용하지 않습니다. |

기본 템플릿은 일반 응답, 문서 요약, 설계 검토, 코드 조사, 코드 구현입니다. 적용하면 설정을 복사하며 원본 템플릿 변경이 기존 에이전트를 자동 수정하지 않습니다. 개인 템플릿 저장 시 모델 바인딩·작업 폴더·명령 권한 등 환경 의존 값은 제거되어 다시 설정해야 합니다.

### 작업 폴더와 허용 도구

**파일 작업에는 세 가지가 함께 필요합니다:** Workspace 도구 실행 모드, 작업 폴더 정책, 허용 도구. 코딩 템플릿을 골랐어도 작업 폴더가 사용 안 함이면 파일 도구가 모델에 제공되지 않습니다.

| 정책        | 사용 방법                                                                                                     |
| ----------- | ------------------------------------------------------------------------------------------------------------- |
| 사용 안 함  | 파일 도구 없이 응답하는 용도입니다.                                                                           |
| 고정 폴더   | 항상 같은 프로젝트를 작업합니다. 예: `C:\Work\MyProject`. 현재 가장 단순하게 파일 작업을 설정하는 방법입니다. |
| 호출자 폴더 | 허용 루트 안에서 매 실행마다 작업 폴더를 전달합니다. 클라이언트의 현재 폴더를 자동 감지하는 방식이 아닙니다.  |

호출자 폴더 시험 예: 정책을 호출자 폴더, 허용 루트를 `C:\Work`로 설정하고 **시험 호출 작업 폴더**에 `C:\Work\ProjectA`를 입력합니다. 다른 실행에는 `C:\Work\ProjectB`를 지정할 수 있습니다. 허용 루트 밖 경로와 호출 작업 폴더 누락은 거부됩니다.

시험 입력의 `input.workspace`는 프롬프트 문자열입니다. **시험 호출 작업 폴더라는 별도 권한 입력을 대신하지 않습니다.** 외부 호출에서 호출자 폴더를 전달하는 사용성은 개선 대상입니다. 전체 파일 접근 허용 정책도 요청 사항이며 현재 선택 가능한 기능은 아닙니다.

| 허용 도구      | 하는 일                               | 조건·사용 예                                                                                    |
| -------------- | ------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `list_files`   | 파일·폴더 목록 탐색                   | 프로젝트 구조 파악. .git, node_modules, 빌드 폴더 등 일부 디렉터리는 목록 탐색에서 제외합니다.  |
| `read_file`    | 텍스트 파일 읽기                      | 줄 단위 읽기와 현재 내용의 해시를 제공합니다.                                                   |
| `search_text`  | 문자열 검색                           | 정규식이 아닌 literal 텍스트 검색입니다. 함수명·설정 키를 찾습니다.                             |
| `write_file`   | 새 파일 생성 또는 기존 파일 전체 교체 | 기존 파일 변경에는 먼저 읽어 얻은 expectedHash가 필요합니다.                                    |
| `replace_text` | 특정 텍스트 교체                      | 기대 해시가 일치하고 대상 문장이 정확히 한 번 있어야 합니다.                                    |
| `run_command`  | 등록한 실행 파일 호출                 | 허용 명령 JSON의 commandId로 선택합니다. 체크만 하고 명령을 등록하지 않으면 실행할 수 없습니다. |

읽기·조사용은 앞의 세 도구, 편집용은 write_file·replace_text까지 선택합니다. 테스트 프로그램 실행이 필요할 때 run_command와 실제 실행 파일을 등록합니다.

허용 명령 JSON 예시(설치 경로는 본인 환경에 맞게 변경):

```json
[
  {
    "commandId": "node",
    "executable": "C:\\Program Files\\nodejs\\node.exe",
    "label": "Node.js"
  }
]
```

commandId는 모델이 선택하는 이름이고 executable은 실행할 프로그램의 절대 경로입니다. 인수와 상대 작업 디렉터리는 호출 시 전달됩니다. 쉘 명령 문자열을 자동 해석하지 않습니다. 실행 파일의 모든 인수 조합에 OS 격리가 적용되는 것은 아니므로, 프로그램 자체의 접근 범위는 파일 도구의 폴더 제한과 다를 수 있습니다.

파일 도구는 작업 폴더 기준 상대 경로를 사용하며 폴더 밖 이동과 심볼릭 링크 경로를 차단합니다. 파일 크기·검색 결과·반환량 제한이 있어 잘린 결과는 실행 관측에서 확인해야 합니다. 모델의 답변과 실제 도구 실행 기록을 함께 확인하세요.

### 시험 실행과 실행 기록

초안을 저장하고 현재 스키마에 맞는 시험 입력 폼을 채웁니다. 문자열·숫자·boolean·enum은 일반 폼을, 중첩 객체·배열 등은 고급 JSON과 생성된 예제를 사용합니다. 일반 문장을 JSON 편집기에 그대로 붙이면 JSON 객체 오류가 납니다.

미리보기는 전달할 메시지를 확인하고, 시험 실행은 모델을 실제 호출하므로 클라우드 비용이 발생할 수 있습니다. 대기·실행 중 상태가 먼저 표시되며 완료 후 최종 답변이 자동 표시됩니다. 조회 연결이 끊어지면 다시 조회를 사용합니다.

실행 기록에서 에이전트·상태·결과·오류와 상세 정보를 확인합니다. queued는 대기, running은 실행 중, completed는 완료, failed는 실패, cancelled는 취소, interrupted는 서비스 중단 등으로 종료된 상태입니다. 취소 요청 직후에는 정리가 끝날 때까지 기다릴 수 있고 이미 반영된 파일 변경이 자동 복원되지는 않습니다.

시간 제한은 작업 대기·실행 시간을 제한합니다. 모델 턴 수는 모델 호출 반복 횟수, 도구 호출 수는 실제 도구 사용 횟수 상한입니다. 제한에 도달한 결과는 정상 완료와 구별해 확인합니다.

### 설정 및 데이터 관리

| 항목                       | 의미                                                                                                        |
| -------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 실행 본문·이벤트 보존 기간 | 입력·출력·이벤트 상세 보관 기간입니다. 만료된 상세는 정리될 수 있으므로 필요한 결과는 별도로 보관합니다.    |
| 전역 최대 동시 실행        | 모든 프로바이더를 합친 동시 작업 상한입니다.                                                                |
| 최대 대기 작업             | 실행 슬롯을 기다리는 작업의 접수 상한입니다. 가득 차면 새 요청이 거부됩니다.                                |
| 설정 내보내기              | 환경 간 설정 이동용입니다. 인증값·작업 폴더·허용 명령 등은 그대로 공유하지 않습니다.                        |
| 설정 가져오기              | 파일 선택 후 충돌 미리보기를 확인하고 적용합니다. 가져온 에이전트는 비활성 초안으로 재설정·시험해야 합니다. |
| 백업                       | DB 백업입니다. 설정 내보내기와 다르며 전체 환경을 자동 복구하는 설치 파일이 아닙니다.                       |

기본 데이터 위치는 `%LOCALAPPDATA%\MCPex`입니다. DB와 secrets.json은 소스와 별도로 저장하며 이 저장소에 업로드하지 않습니다. 비밀값은 Windows 현재 사용자 DPAPI로 보호하므로 다른 PC나 계정으로 파일만 복사해 사용할 수 있다고 가정하지 마세요. 백업 교체 후 전체 복구는 별도 검증 대상입니다.

### 문제 해결

| 증상                          | 확인할 내용                                                                                                 |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 설정 실행기가 안 열림         | Node.js와 빌드를 확인하고 프로젝트 폴더에서 `node .\apps\cli\dist\src\index.js open`으로 오류를 확인합니다. |
| 브라우저가 안 보임            | 기존 브라우저 새 탭과 Windows 기본 브라우저를 확인합니다.                                                   |
| 인증 오류                     | 설정 실행기로 다시 접속하고 서비스와 화면이 같은 데이터 폴더를 사용하는지 확인합니다.                       |
| 모델 시험 실패                | URL·인증·모델 ID·어댑터와 로컬 서버 실행 여부를 확인합니다.                                                 |
| 파일을 못 읽음                | 실행 모드·폴더 정책·허용 도구를 모두 확인합니다. 입력에 경로만 적어서는 권한이 설정되지 않습니다.           |
| 프롬프트 변경이 반영되지 않음 | 초안 저장 후 적용 버전을 생성했는지 확인합니다.                                                             |
| 작업이 대기함                 | 전역·프로바이더·그룹 제한과 작업 폴더 잠금을 확인합니다.                                                    |
| 파일 변경 충돌                | 최신 내용을 다시 읽고 수정합니다.                                                                           |
