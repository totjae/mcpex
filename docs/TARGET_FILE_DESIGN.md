# 실행별 대상 파일 지정 설계

## 1. 상태와 목적

**2026-09-23 1차 구현 완료·자동 검증 일부 완료.** 아래는 설계 계약이며, 현재 구현·미검증 범위는 이 절 끝에 구분한다.

현재 optional 설정, 공통 targets 입력, 접수 전 경로 검증·실행 스냅샷, ID 기반 파일 도구, 직접 경로 도구·명령 차단, 기본 코드 구현 템플릿 및 시험 UI가 연결됐다. 2026-09-24 T01에서 성공 이벤트 기반 대상 변경 목록을 관리 API와 화면에도 연결했다. 단위·모의 공급자 UI/MCP 실행과 새 대상 편집 화면 Edge E2E를 수행했다. 대기 중 파일 교체·동시 경합, 전체 작업 폴더 정책 조합, 실제 라이트 모델 검증은 아직 수행하지 않았다. 따라서 아래 전체 인수 기준을 검증 완료로 간주하지 않는다.

메인 에이전트가 정확한 절대 경로를 전달해도 서브 모델이 파일명만 추출해 다른 기준의 상대 경로로 호출할 수 있다. 이번 설계는 경로를 프롬프트에 추가하는 데 그치지 않고, MCPex가 실행별 대상 경로를 확정하고 내부 파일 도구에 연결한다.

보장할 범위는 **대상 ID가 검증된 경로로 연결되고, 모델이 다른 경로로 대체하여 파일 도구를 실행할 수 없다는 것**이다. 메인이 잘못 지정한 파일, 모델의 잘못된 편집 내용, 실제 과제 성공까지 보장하지 않는다. OS 수준 sandbox나 외부 프로세스의 동시 파일 교체 방지로 설명하지 않는다.

## 2. 호출 계약과 기존 호환성

기본 코딩 템플릿에 선택 입력 `targets`를 제공한다. 이 계약을 사용하는 에이전트는 새 설정 `runtime.targetBinding: "optional"`을 명시한다. 기존 설정은 기본 `"off"`이며 자동 변경하지 않는다.

```json
{
  "task": "입력 파일을 읽고 결과를 작성해줘",
  "targets": [
    { "id": "input", "path": "C:\\Work\\ProjectA\\input.txt", "access": "read" },
    { "id": "output", "path": "C:\\Work\\ProjectA\\output.txt", "access": "write" }
  ]
}
```

- 공개 MCP 도구 arguments의 `targets`를 서버가 구조화된 값으로 처리한다. 관리 시험은 동일하게 `input.targets`로 전달한다. 별도 MCP 메타데이터 지원을 요구하지 않는다.
- optional 에이전트에서 targets 생략은 기존 탐색 실행, 유효한 비어 있지 않은 targets 제공은 대상 지정 실행이다. `[]`, null, 잘못된 값은 입력 오류이며 탐색 실행으로 fallback하지 않는다.
- off 에이전트의 기존 사용자 입력에 우연히 targets라는 필드가 있어도 대상 계약으로 해석하지 않는다. optional 활성화 시 입력 스키마의 targets가 공통 계약과 맞는지 적용 단계에서 검증하고 충돌이면 거부한다. 프롬프트 필드명만 보고 자동 활성화하지 않는다.
- 기본 템플릿과 사용자 정의 에이전트는 선택 적용한다. 기존 사용자 스키마·프롬프트·활성 상태를 일괄 수정하지 않는다. UI 시험 입력도 대상 목록 추가/삭제와 id·path·access 입력을 지원해야 한다.
- targets는 파일만 지정한다. 폴더, glob, 재귀 범위, 자동 파일 검색은 첫 구현에서 지원하지 않는다. 대상 없는 범용 코딩의 기존 탐색 기능은 유지한다.

각 항목의 필수 필드는 id/path/access이며 추가 필드는 거부한다. id는 `[A-Za-z][A-Za-z0-9_-]{0,63}`, 실행 내 중복 금지다. access는 read/write/readwrite 중 하나다. 최대 32개로 제한한다. 같은 정규화 경로를 서로 다른 ID로 중복 지정하는 것도 첫 버전에서는 거부한다.

## 3. 접수와 경로 확정

1. 기존 정책으로 실제 작업 기준을 확정한다. fixed는 설정된 루트, caller는 기존 메타데이터/UI workspace로 선택한 폴더, full은 절대 경로 계약을 유지한다. targets가 caller의 workspace 누락을 대신하거나 none 정책을 활성화하지 않는다.
2. 각 path를 공통 파일 경로 처리로 정규화한다. scoped 상대 경로는 해당 실행 루트 기준, 절대 경로는 범위 내부일 때만 허용한다. full은 절대 경로만 받는다. 실제 경로는 MCPex 실행 호스트 기준이다.
3. 접근 범위·모호한 경로·링크 정책·대상 중복을 검사한다. 본문의 workspace나 task를 해석해 기준을 바꾸지 않는다. 잘못된 대상 하나라도 있으면 모델 호출 전에 전체 접수를 거부한다.
4. 검증된 ID→경로·권한 매핑을 실행 스냅샷에 고정한다. 대기 중 설정 변경으로 대상을 재선택하지 않는다. 실제 파일 접근 시에는 경계·링크·해시 검사를 다시 수행한다.

읽기 대상과 readwrite 대상은 기존 일반 파일을 대상으로 한다. 쓰기 전용 대상은 **새 파일 생성 전용**이며 기존 파일이면 거부한다. 존재 여부 검사는 모델 호출 전 오류 안내를 위한 것이고, 실제 생성 순간에도 배타 생성으로 경합을 처리해야 한다. 읽기·쓰기 권한 여부는 실제 OS 작업 결과로 판단하며 사전 검사만으로 보장하지 않는다.

대상 계약 오류에는 targetId와 정형 사유를 포함하고 원시 절대 경로는 자동 반사하지 않는다. 정책 위반·없는 입력·기존 출력·대상 ID 중복을 구분한다. 구체적 오류 코드 명칭은 구현 시 API_SPEC에 동기화한다.

## 4. 서브 모델의 내부 도구

대상 지정 실행에서 모델에는 대상 ID·access와 다음 허용 도구만 제공한다. 경로 문자열을 스키마나 시스템 메시지에 자동 주입하지 않는다.

| 도구 | 인자 | 허용 조건과 동작 |
| --- | --- | --- |
| read_target | targetId, startLine?, maxLines? | read/readwrite 및 기존 read_file 허용. 기존 파일 읽기 결과와 해시 반환 |
| write_target | targetId, content, expectedHash? | write 또는 readwrite 및 기존 write_file 허용. write는 새 파일 배타 생성, readwrite는 기존 해시 필수 |
| replace_target | targetId, oldText, newText, expectedHash | readwrite 및 기존 replace_text 허용. 기존 치환·해시 계약 유지 |

- 모델은 대상 ID만 선택한다. 예: `read_target({"targetId":"input"})`. 알 수 없는 ID, 임의 path 인자, 권한 없는 작업은 실행 경계에서도 거부한다.
- runtime의 기존 도구 허용 목록과 target access의 **교집합**만 제공한다. 요청 권한을 수행할 기존 도구가 없으면 접수 단계에서 설정 오류로 알린다. readwrite 편집에는 read_file과 적어도 하나의 쓰기 도구가 필요하다.
- 대상 지정 실행에서는 read_file/write_file/replace_text/list_files/search_text 등 직접 경로를 받는 도구를 모델에 제공하지 않고 실행기에서도 차단한다. 첫 버전의 탐색은 read_target 범위로 한정한다.
- **run_command도 대상 지정 실행에서 제외·차단한다.** 명령 인자나 실행 코드로 다른 파일에 접근할 수 있어 대상 제한 보장과 함께 제공할 수 없다. 명령 시험이 필요한 범용 작업은 기존 탐색 실행을 사용한다. 이 제한을 UI와 공개 도구 설명에 명시한다.
- 기존 WorkspaceTools를 공통 실행기로 재사용한다. 별도의 파일 IO 구현을 복제하지 않는다. 도구 결과에는 targetId를 사용하고 서버가 반환하던 실제/상대 path는 대상 결과에서 노출하지 않는다.
- 도구 횟수·모델 턴·출력 크기·취소·시간 제한·잠금은 기존 정책을 유지한다. 별도 파일 단위 잠금 최적화는 이번 범위에 넣지 않는다.

## 5. 쓰기 안전성과 오류 복구

- write는 읽기 권한 없이 새 출력만 만드는 용도다. 기존 파일 갱신은 readwrite로 명시하고 read_target에서 얻은 expectedHash를 사용한다. write_target이 기존 파일을 자동으로 덮어쓰지 않는다.
- 같은 대상이 외부에서 변경되면 기존 HASH_CONFLICT로 거부한다. 재읽기 후 모델이 변경 내용을 다시 검토해야 하며 자동 강제 덮어쓰기는 없다.
- 입력 파일이 사라지거나 권한이 없으면 해당 대상의 실제 실패만 보고한다. 부모 폴더 목록 조회로 우회하거나 동명 파일을 찾아 대상 매핑을 바꾸지 않는다.
- task의 자유문장과 targets의 의미적 모순을 서버가 모두 검출한다고 가정하지 않는다. 파일 도구의 실행 대상은 targets를 따르고, 모델에는 충돌이 보이면 쓰기 전에 확인하도록 지시한다. 확인이 필요한 경우 파일을 변경하지 않고 결과를 반환한다.
- 모델이 부여된 ID 중 잘못된 것을 선택할 가능성은 남는다. read/write 구분으로 줄일 수 있지만 여러 readwrite 대상 사이의 작업 내용 정확성까지 자동 보장하지 않는다.

## 6. 경로 공개와 실행 기록

- 메인이 제공한 path는 MCP 클라이언트와 MCPex가 이미 받는 값이다. 이를 메인에게도 비공개라고 설명하지 않는다.
- MCPex가 대상 매핑을 모델 입력에서 분리한다. optional 실행의 프롬프트 렌더링용 targets는 id/access 목록으로 대체해 `{{input.targets}}`를 사용해도 자동 경로 재주입이 없게 한다. 미리보기는 실제 모델 메시지와 일치해야 한다. 원본 구조는 서버 검증·로컬 기록용으로만 사용한다.
- 사용자가 task/context/사용자 시스템 프롬프트 또는 파일 본문에 적은 경로는 별개다. 그런 경로까지 자동 삭제하거나 모델에 전송되지 않는다고 보장하지 않는다. 파일 내용은 기존처럼 선택한 공급자에게 전달된다.
- 로컬 실행 스냅샷에 원본 입력과 확정 대상 매핑을 저장하되 기존 인증·실행 내용 보존/삭제 정책을 적용한다. 공개 MCP 결과·일반 이벤트는 targetId/operation/error code 중심으로 기록하며 실제 루트를 새로 포함하지 않는다.
- 결과의 changes는 targetId로 식별 가능한 형태를 추가한다. 기존 path 필드를 억지로 ID 문자열로 채우지 않는다. 선택 필드 확장 등 호환 가능한 계약을 정의하고 기존 탐색 실행 결과는 유지한다.
- 실행 완료와 과제 검증 상태는 기존 구분을 유지한다. 대상 매핑이 정확하다는 이유로 과제 검증을 passed로 바꾸지 않는다.

## 7. 구현 순서와 위치

1. contracts/API 명세에 optional target binding, 공통 targets 스키마와 결과 식별 계약 추가. 기존 설정의 off 기본값 및 template/import/export 처리 정의.
2. 서버 접수에서 공통 경로 검증·실행 스냅샷 대상 매핑 확정. 설정 경로 정규화와 실행 시 검사가 같은 정책을 사용하도록 tools 모듈을 재사용.
3. 서버 모델 도구 제공과 실행 dispatch에 대상 전용 도구 연결. 직접 경로 도구/명령은 스키마와 실제 실행 양쪽에서 차단.
4. 기본 코딩 템플릿, 편집 UI, 시험 폼, 미리보기, 실행 결과의 targetId 표시 연결. 기존 에이전트는 선택 적용.
5. 아래 회귀 검증 후 API_SPEC/DATA_MODEL/PRODUCT_SPEC/IMPLEMENTATION_STATUS/TEST_PLAN을 실제 구현에 맞춰 갱신. 이 문서의 계획과 완료 상태를 구분.

## 8. 인수 기준

- 공개 MCP와 UI 시험에서 같은 targets로 같은 파일에 접근하고, 서브 모델 요청에는 자동 주입된 실제 대상 경로가 없다. 모델에는 ID/access와 허용 대상 도구가 전달된다.
- 서브 모델이 input.txt 같은 직접 경로나 임의 ID를 요청해도 다른 파일을 읽거나 쓰지 않는다. 미허용 run_command/직접 경로 도구 호출을 실행 경계에서 거부한다.
- 서로 다른 폴더의 동명 파일 중 지정한 대상만 접근한다. 상대/절대 입력은 같은 대상으로 정규화되며 중복 ID/동일 경로 별칭은 거부한다.
- fixed/caller/full/none, 범위 밖·링크·모호한 경로, 대기 후 파일 교체·삭제, 실제 접근 거부를 확인한다. OS 수준 경합을 모두 막았다고 선언하지 않는다.
- write의 새 파일 생성, 기존 파일 거부와 동시 생성 충돌; readwrite의 읽기·해시 기반 수정·충돌; read 대상 쓰기 차단을 각각 검증한다.
- targets 생략은 기존 탐색 도구 흐름 유지, 빈/잘못된 targets는 자동 fallback 없음, off 사용자 스키마의 동명 필드는 기존 의미 유지.
- 미리보기·실제 공급자 메시지·MCP 결과·이벤트의 경로 노출 규칙을 검사한다. 파일 내용의 우연한 경로 문자열까지 제거하는 테스트로 혼동하지 않는다.
- 모의 공급자와 실제 파일 도구 통합 시험을 먼저 수행하고, 실제 라이트 모델로 인공 입력→새 출력 시험을 별도 수행한다. 모델이 도구를 안 쓰고 답하면 미검증으로 기록하며 성공으로 합산하지 않는다.

## 9. 보류 범위

폴더 대상/재귀 탐색, 대상 전용 검색, 대상 제한을 유지하는 명령 실행, 파일 핸들 기반 경합 강화, 사용자 설정에 영구 고정 대상을 저장하는 기능은 이번 범위에서 제외한다. 향후 필요성이 확인되면 별도 설계한다.
