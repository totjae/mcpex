# 제품 및 화면 명세

## 대상 파일 변경 결과 표시 (2026-09-24)

대상 지정 시험 결과와 실행 기록은 성공한 생성·수정/텍스트 교체의 대상 ID를 표시한다. 읽기만 한 경우에는 기록된 변경이 없다고 표시하고, 기록 보존 기간이 끝난 경우에는 확인할 수 없다고 표시한다. 실행 실패 뒤에도 그 전에 성공한 파일 변경을 숨기지 않는다. 원본 대상 목록은 실제 변경 목록의 대용으로 사용하지 않는다.

## 실행별 대상 파일 지정 (2026-09-23 1차 구현)

코드 구현 기본 템플릿은 선택적 targets를 지원한다. 에이전트 편집에서 대상 지정 사용 여부를 선택할 수 있고, 시험 입력 폼에서 대상 ID·경로·읽기/새 파일 쓰기/읽고 수정 권한을 추가·삭제할 수 있다. 대상 지정 실행의 모델에는 ID 기반 도구만 제공되며 직접 경로 도구와 명령 실행은 사용할 수 없다. 대상 생략은 기존 탐색 실행이다. 경로는 MCP 클라이언트와 MCPex에 전달되지만 MCPex가 모델 프롬프트에 자동 주입하지 않는다. 파일 본문이나 사용자가 작성한 프롬프트 속 경로까지 제거한다는 의미는 아니다. 화면 E2E·실제 모델 사용성은 미검증이다.

2026-09-23 UX13 보완: 등록된 프로바이더 카드에서 같은 ID의 설정을 편집한다. 현재값 조회·변경 취소·미저장 전환 확인을 제공하고, 프로필 변경 시 어댑터·실행 위치·URL의 변경 예정값을 보여준다. 인증값 원문은 표시하지 않으며 유지·교체·제거를 명시적으로 선택한다. 설정과 키 작업의 부분 실패, revision 충돌 및 최신값 조회·다시 불러오기를 구분한다. 저장된 연결의 모델 조회는 별도 버튼으로 시험한다. 접수된 실행은 접수 시점의 스냅샷을 사용한다.

2026-09-23 UX10–UX12 보완: 모델 선택·목록·삭제 확인은 `모델 표시명 (프로바이더명)`을 사용한다. 프로바이더 이름이 없으면 확인 필요로, 같은 이름이 중복되면 비밀이 아닌 provider ID로 구분한다. 실제 API modelId가 표시명과 다를 때만 목록에 별도 표시하며 저장 참조 model.id는 변하지 않는다. 로컬 에이전트 설정 화면은 fixed 작업 폴더의 실제 실행 기준과 하위 경로 예시를 표시하지만, MCP 공개 설명에 절대 경로를 넣지 않는다.

## 2026-09-15 실행 방식 변경

설정 실행 파일을 더블클릭해 관리 웹 화면을 연다. 설정 화면 또는 MCP 클라이언트 연결이 서비스를 필요로 할 때 자동 시작하며 사용자가 별도 serve 터미널을 관리하지 않는다. 활성화·비활성화 상태는 영속화하고 재시작 시 임의로 변경하지 않는다. 활성 에이전트는 연결 후 바로 제공하고 비활성 에이전트는 명시적으로 다시 활성화하기 전까지 제공하지 않는다. 설정 화면을 닫아도 활성 도구 사용은 유지된다. 로컬 추론 서버 시작·모델 로딩과 OS 로그인 자동 실행은 범위 밖이다.

## 1. 확정 범위

설계 기준선 v1 / 2026-09-13. Windows 11 단일 사용자 로컬 서비스가 첫 지원 대상이다. UI는 한국어를 기본으로 한다. 다른 OS는 인터페이스 확장을 고려하되 v1 지원을 약속하지 않는다.

### v1 필수

- 클라우드 API·로컬 서버 연결, 모델 수동 등록 및 지원되는 경우 목록 조회.
- 다양한 클라우드 프로바이더와 로컬 모델 서버 연결. 공급업체별 연결 정의는 프로바이더 프로필로 관리하고, 실제 요청 형식은 명시된 프로토콜 adapter가 담당한다.
- 초기 프로토콜은 OpenAI 호환 Chat Completions, Anthropic Messages, Google Gemini generateContent이며, provider-manager-v1.16.3의 등록 정의·모델 설정 구조를 확장 기준으로 사용한다.
- 로컬 모델은 OpenAI 호환 서버(LM Studio, Ollama OpenAI 호환 endpoint, llama.cpp, vLLM, LocalAI 등)를 우선 지원하고, native API가 필요한 서버는 별도 adapter로 추가한다. 모델 자동 다운로드·실행은 지원하지 않는다.
- 일반 응답과 자체 도구 사용 실행. 모델별 기능 시험 및 미확인 상태 표시.
- 에이전트 CRUD·복제, 프롬프트·입출력 편집, 템플릿 적용·저장·가져오기·내보내기.
- 에이전트별 MCP 도구, 복수 활성화, 초안과 적용 버전 분리.
- 시험 실행, 실행 기록, 취소, 시간·반복 한도, 대기열.
- 로컬 웹 UI, STDIO MCP 브리지, 로컬 인증, 비밀정보 별도 저장.

### 후속 범위

출력 검증 모델, 자동 재작업, OpenAI Responses 전용 어댑터, 외부 실행기(Codex CLI 등), 외부 MCP 도구 가져오기, 모델 자동 로딩·다운로드, 팀/원격 서비스, 설치 프로그램, 대화 세션 재개. 다만 provider-manager 기반의 프로바이더 프로필·모델 설정 레지스트리는 v1 연결 범위에 포함한다.

v1에 포함하지 않는 기능을 작동하는 것처럼 보이는 토글로 제공하지 않는다. 별도 일정이 정해지기 전 후속 기능은 보류 상태다.

## 3. 화면과 사용자 흐름

작업 폴더 정책 표시명은 `fixed`를 **지정 폴더와 하위 전체**, `caller`를 **허용 범위 안에서 호출마다 선택**으로 사용한다. fixed는 지정한 폴더와 모든 하위 폴더, caller는 허용 범위 안에서 이번 호출에 선택한 폴더와 그 하위를 포함한다. caller의 시험 입력은 **시험 실행에서 사용할 폴더**로 표시하고 실제 폴더임과 MCP 호출 기본값이 아님을 안내한다. 저장 형식·권한 동작은 기존 계약을 유지한다.

| 메뉴             | 주요 내용                                                        |
| ---------------- | ---------------------------------------------------------------- |
| 프로바이더       | 목록, 등록 프리셋/직접 입력, 인증 변경, 연결 시험, 소속 모델     |
| 에이전트         | 이름·도구 이름·모델·활성·초안 변경·연결 상태, 생성·복제          |
| 템플릿           | 기본/사용자 템플릿, 미리보기, 템플릿에서 생성, 가져오기·내보내기 |
| 실행 기록        | 상태·에이전트 필터, 입력·결과·도구 실행·오류·취소                |
| 설정 및 MCP 연결 | 저장 위치, 기록 보존, 실행 제한, STDIO 연결 정보                 |

프로바이더 등록은 이름/어댑터/기본 URL/인증 → 저장 → 모델 조회 또는 직접 입력으로 진행한다. URL·인증 확인, 목록 조회, 짧은 생성 시험은 독립 결과로 표시한다. 생성 시험은 사용자 버튼으로만 호출한다.

에이전트 편집 탭: 기본 정보 / 모델 / 프롬프트 / 입력·출력 / 도구·실행 / 시험 실행.

MCP 연결 정보 탭은 현재 설치 환경의 로컬 STDIO 등록 값을 Codex 화면 순서인 이름·유형·실행 명령·개별 인자·환경 변수 키/값·패스스루·작업 디렉터리로 제공한다. 필드 복사는 원시 값을 사용하고 설정 파일 편집용 `config.toml` 전체 설정은 별도로 제공한다. MCPex 서버는 클라이언트마다 한 번 등록하고 활성 적용 에이전트는 각각의 `toolName` 도구로 노출한다. 관리 API 응답과 실제 클라이언트 연결 여부를 구분하며, 비활성·미적용 상태 및 도구 목록 갱신·재연결 절차를 안내한다. 현재 원격 연결은 지원하지 않으며 등록 예제에는 인증 토큰이나 모델 API 키를 포함하지 않는다.

- 기본 정보: 표시 이름, MCP 이름, 도구 설명, 태그.
- 모델: 등록 모델과 에이전트별 생성 옵션. 기본값 상속과 재정의를 구별.
- 프롬프트: 시스템 프롬프트, 입력 메시지 템플릿, 실제 메시지 미리보기.
- 입력·출력: 폼 편집기와 제한된 JSON Schema 고급 편집기. 오류 위치 표시.
- 도구·실행: 응답/도구 사용 모드, 작업 폴더 정책, 선택 도구와 실효 도구, 명령 설정, 제한 시간. 고정·호출자 폴더 안에서는 상대 경로와 범위 내부 절대 경로를 모두 처리하되 실제 설정 경로를 MCP·모델 설명에 공개하지 않는다. 호출자 폴더는 허용 루트와 매 호출 실제 폴더를 구분하고 클라이언트 메타데이터 지원 여부를 안내한다. 전체 접근은 고위험 선택지로 분리하고 현재 OS 사용자 권한, 절대 경로 요구와 권한 상승이 아님을 표시한다. 실효 파일 도구의 모델 제공자 전송 범위와 명령의 현재 사용자 권한·비-sandbox 실행도 함께 표시한다.
- 시험 실행: 초안으로 실행하고 MCP 공개 없이 결과 확인.

시험 실행·실행 기록에서 `completed`는 **실행 완료**로 표기하고 과제 검증 상태를 별도로 보여준다. 현행 검증 기준이 없는 작업은 **미검증**이며 실제 명령 종료 코드·도구 실패 코드는 근거로만 표시한다. 모델이 완료를 주장하거나 변경 파일이 없다는 사실만으로 통과·실패를 자동 판정하지 않는다.

저장은 초안만 갱신한다. 적용은 새 불변 버전을 생성한다. 활성화는 적용 버전이 있어야 가능하다. 활성 에이전트 수정 후 적용하면 이후 호출부터 새 버전을 쓴다. 실행 중 작업은 기존 스냅샷을 유지한다.

비활성화는 새 호출을 차단한다. 이미 접수된 대기·실행 작업은 유지하며 취소는 별도 동작이다. 모델·프로바이더 수정도 참조 에이전트의 재적용 전에는 공개 버전에 반영하지 않는다. 인증 키 교체는 예외로 이후 실행이 현재 비밀값을 사용한다.

## 4. 템플릿

기본 템플릿: 일반 응답, 문서 요약, 설계 검토, 코드 조사, 코드 구현.

- 이름·설명, 시스템 프롬프트, 입력 템플릿, 입력 스키마, 출력 설정, 실행 모드, 도구 정책, 한도, 권장 기능을 포함.
- 사용자 모델 ID, 비밀정보, 절대 작업 폴더를 기본 템플릿에 넣지 않는다.
- 적용 시 값을 복사한다. 이후 템플릿 변경은 기존 에이전트를 변경하지 않는다.
- 템플릿 재적용은 차이 미리보기 후 선택한 설정 묶음만 초안에 반영한다.
- 코드 구현 템플릿은 파일 읽기·검색·편집을 기본으로 한다. 명령 실행은 기본 꺼짐이며 사용자가 설정한다.
- 수정한 에이전트를 개인 템플릿으로 저장할 때 모델 바인딩·인증·작업 폴더·명령 실행 허용은 제거하고 필요한 재설정 항목을 안내한다.

## 5. 편집과 활성화 기준

MCP 이름은 `^[a-z][a-z0-9_]{0,47}$`, 전역 유일, `mcpex_` 접두사는 예약한다. 최초 적용 후 이름 변경은 복제로 처리한다. 표시 이름은 자유롭게 변경한다.

입력 스키마는 최상위 object. 일반 템플릿은 task 필수와 context 선택이다. 코드 템플릿은 task만 필수이고 workspace/scope/requirements는 선택 입력이다. workspace는 작업 대상 위치를 설명하는 문맥 정보이며 파일 도구의 실행 기준을 바꾸지 않는다. scope는 조사·수정 범위이며 파일 접근 권한은 실행 정책이 결정한다. 코드 구현 템플릿은 scope를 실제 모델 메시지에 포함한다.

시스템 프롬프트는 사용자 편집 원문을 유지한다. 입력 메시지 템플릿은 `{{input.task}}` 형태의 입력 키 치환만 허용하고 코드·파일·환경변수 평가를 하지 않는다. 비문자열은 JSON으로 치환한다. 누락된 선택 항목은 빈 문자열, 존재하지 않는 스키마 키 참조는 저장 오류다.

실행기가 생성하는 도구 설명과 JSON 출력 지침은 별도 표시하고 미리보기에 포함한다. MCP 도구 설명에는 적용 버전의 실효 파일·명령 권한에 맞는 외부 전송·실행 권한 안내를 자동 추가한다. 사용자가 작성한 프롬프트와 실제 강제 실행 정책을 구분한다.

활성화 전 스키마 유효성, 모델 바인딩, 필수 인증 존재, 모드별 기능 호환성을 검사한다. 도구 사용은 해당 조합의 도구 호출 시험이 passed여야 한다. 모델 시험은 작업 품질 보증이 아니다. 응답 모드에서 미시험 모델 활성화는 허용하고 미확인을 표시한다.

## 6. 오류·경계 조건

- 참조 중 모델·프로바이더 삭제는 차단하며 영향받는 에이전트를 표시한다.
- 중복 도구 이름, 구형 초안 저장 충돌, 잘못된 JSON Schema는 구체적 오류를 표시한다.
- MCP 목록 변경을 즉시 반영하지 않는 클라이언트에는 재연결 안내를 제공한다.
- 자유 출력도 실행 상태와 분리해 표시한다. JSON 형식 실패로 원본 답변을 잃지 않는다.
- 연결 오류가 발생해도 등록 설정을 삭제하지 않는다. 자동 모델 대체는 하지 않는다.
- 검증 모델 기능은 v1 범위 밖이다. 향후 원본 결과·검증 의견·실제 실행 관측을 분리한다.
